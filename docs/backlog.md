# AdminForge backlog

Known gaps and deferred work, by area: one table per area, one row per open item. Done items leave the table — the
change that closes one deletes its row and says what changed in `CHANGELOG.md`. (Until 2026-10-21 this file was a
journal of dated sections; `git log -p -- docs/backlog.md` has it.)

**Before adding**, search: `rg -i "<words>" docs/backlog.md`. Extend a row that already covers the gap instead of
adding a near-duplicate. Otherwise add a row to the area it belongs to:

- **Item** — what is missing and where (ids, paths), in a sentence or two; the detail lives behind the link.
- **Status** — `open` (ready to pick up), `blocked` (waits on something outside the repository — a licence, a test
  object, a subscription, a cluster — which the item names), `deferred` (decided not now; the link says why), `decide`
  (needs the owner's decision first), `retired` (Content only: retired content and how to bring it back). A review's
  priority follows a comma: `open, high`.
- **Since** — the day it was first recorded.
- **Owner type** — who acts: `code`, `content`, `docs`, `live` (a check against a real tenant, subscription or cluster,
  read-only unless the item says otherwise) or `owner` (the code owner, or the installation's owner).
- **Link** — where the detail is: a review finding, a licensing finding, a document, the code.

Rows stay one line each (the `<!-- prettier-ignore -->` above every table keeps Prettier from padding them), so a
change is one line of diff. `tests/unit/docs/registers.test.ts` keeps this shape: the nine areas, one table each, no
dated heading, a known status and owner type on every row.
